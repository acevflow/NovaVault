# [`.editorconfig`](../../.editorconfig)

## Purpose

Shared editor settings for every file in the repository, read by any editor with EditorConfig support. It fixes the character set, line endings, final newline, trailing whitespace and indentation so that contributors on Windows, macOS and Linux produce the same bytes, matching the line-ending rules in [`.gitattributes`](.gitattributes.md).

## Public API

| Section            | Key                        | Value   | Purpose                                                       |
| ------------------ | -------------------------- | ------- | ------------------------------------------------------------- |
| top level          | `root`                     | `true`  | Stops the lookup here; no `.editorconfig` above the repository applies. |
| `[*]`              | `charset`                  | `utf-8` | All files are UTF-8.                                          |
| `[*]`              | `end_of_line`              | `lf`    | LF line endings by default.                                   |
| `[*]`              | `insert_final_newline`     | `true`  | Every file ends with a newline.                               |
| `[*]`              | `trim_trailing_whitespace` | `true`  | Trailing spaces are removed on save.                          |
| `[*]`              | `indent_style`             | `space` | Spaces, not tabs.                                             |
| `[*]`              | `indent_size`              | `2`     | Two-space indentation (TypeScript, JSON, YAML, CSS, HTML, TOML). |
| `[*.rs]`           | `indent_size`              | `4`     | Rust uses four spaces, the `rustfmt` default.                 |
| `[*.md]`           | `trim_trailing_whitespace` | `false` | Keeps two trailing spaces, which are a hard line break in Markdown. |
| `[{Makefile,*.mk}]`| `indent_style`             | `tab`   | Make requires tabs in recipes.                                |
| `[*.{bat,cmd,ps1}]`| `end_of_line`              | `crlf`  | Windows scripts use CRLF.                                     |

## Details

### Precedence

Sections are applied in order and later matches override earlier ones, so `[*.rs]`, `[*.md]` and the others change only the keys they set and inherit the rest from `[*]`.

### Agreement with other tools

- **Git.** [`.gitattributes`](.gitattributes.md) stores and checks out text files with LF and `.bat`, `.cmd` and `.ps1` with CRLF, the same split as here, so an editor never writes line endings that Git would then rewrite.
- **Prettier.** Prettier reads `.editorconfig` for `end_of_line`, `indent_style` and `indent_size` unless its own config sets them. [`ui/.prettierrc.json`](ui/.prettierrc.json.md) sets only `singleQuote` and `printWidth`, so the UI's formatting uses these values.
- **rustfmt.** There is no `rustfmt.toml`; rustfmt's default of four spaces and its own line-ending handling agree with `[*.rs]`.

### Security notes

_Not applicable: editor settings have no security impact. Uniform UTF-8 and LF do keep diffs free of invisible changes, which makes review of security-relevant code easier._

## Dependencies

- **Internal**: none.
- **External**: an EditorConfig-aware editor or plugin; Prettier honors it for the UI.

## Used by

- Editors and IDEs of all contributors.
- Prettier, through `npm run format` and `npm run format:check` in `ui/`.

## Tests

_Not applicable: a configuration file has no tests. Prettier's check in CI and `npm run check` enforce the UI formatting; `cargo fmt --check` enforces Rust formatting._

## Notes

- The `[{Makefile,*.mk}]` and `[*.{bat,cmd,ps1}]` sections are forward-looking: the repository contains no Makefile, `.mk`, `.bat`, `.cmd` or `.ps1` file today.
- Only Prettier and rustfmt enforce formatting in CI; the other settings (for example a final newline in TOML or YAML files) depend on each contributor's editor.
