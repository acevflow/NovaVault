# Security Policy

## 🔒 Security at NovaVault

Security and privacy are core goals of NovaVault.

Because NovaVault is designed to store sensitive information such as passwords, documents, and personal files, security issues are taken seriously.

However, **NovaVault is currently in early development and should not be considered production-ready**. Do not use it to store critical or irreplaceable data yet.

## Reporting a Vulnerability

If you believe you have found a security vulnerability, please **do not open a public issue**.

Instead, report it privately to the project maintainers so it can be investigated and fixed before the vulnerability is publicly disclosed.

Please include:

* A clear description of the vulnerability.
* Steps to reproduce it.
* The potential impact.
* Any relevant screenshots, logs, or proof of concept.

## Responsible Disclosure

Please allow the maintainers reasonable time to investigate and address reported vulnerabilities before publicly disclosing them.

We appreciate responsible security research and anyone who helps make NovaVault safer.

## Security Development

NovaVault will prioritize:

* Strong, well-established cryptographic libraries.
* Secure key management.
* Local-first data storage.
* Minimal collection of user information.
* Regular dependency updates.
* Security-focused code reviews and testing.

Security decisions will be documented as the project develops.
