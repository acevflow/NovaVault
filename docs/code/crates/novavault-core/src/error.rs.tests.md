# [`crates/novavault-core/src/error.rs`](../../../../../crates/novavault-core/src/error.rs#L163) (tests)

## Purpose

The inline `#[cfg(test)] mod tests` of `error.rs` pins the user-visible messages of the two errors that must stay generic (so they never reveal whether the key or the data was at fault) and checks the `CryptoError` to `VaultError` conversion. No test vectors: the expected values are the exact `Display` strings.

## Public API

| Name                              | Kind | Signature                               | Description                                                              |
| --------------------------------- | ---- | --------------------------------------- | ------------------------------------------------------------------------ |
| `decryption_message_is_generic`   | test | `fn decryption_message_is_generic()`    | `CryptoError::Decryption` displays a fixed message naming both causes.   |
| `unlock_failure_message_is_generic` | test | `fn unlock_failure_message_is_generic()` | `VaultError::InvalidCredentials` displays a fixed message naming all causes. |
| `crypto_errors_convert`           | test | `fn crypto_errors_convert()`            | `VaultError::from(CryptoError::Random)` is `VaultError::Crypto(Random)`. |

## Details

### `decryption_message_is_generic`

Asserts `CryptoError::Decryption.to_string()` equals `decryption failed: wrong key or corrupted data`. A change to the message that names a single cause breaks the test on purpose.

### `unlock_failure_message_is_generic`

Asserts `VaultError::InvalidCredentials.to_string()` equals `wrong password or recovery code, or corrupted key slot`. This is the message an unlock attempt shows for a wrong secret and for a damaged slot alike.

### `crypto_errors_convert`

Converts `CryptoError::Random` with `VaultError::from` and asserts it matches `VaultError::Crypto(CryptoError::Random)`, the variant generated by `#[from]`. This is what lets vault code use `?` on core crypto results.

## Notes

- Only two of the ten `CryptoError` variants and one of the twelve `VaultError` variants have their message pinned here. The other messages are not tested in this module.
- `VaultError::Io`'s `#[from] std::io::Error` conversion is not tested here; it is exercised indirectly by I/O tests such as `vault::tests::missing_file_is_an_io_error`.
