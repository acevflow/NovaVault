# [`src-tauri/build.rs`](../../../src-tauri/build.rs)

## Purpose

The Cargo build script of the shell. It runs `tauri-build`, which embeds [`tauri.conf.json`](tauri.conf.json.md), the capability files and the frontend assets into the binary, and it declares the app's own commands so Tauri generates one `allow-<command>`/`deny-<command>` permission pair per command. Tauri then rejects any IPC call that the window's capability does not grant, which makes [`capabilities/default.json`](capabilities/default.json.md) the exact allow-list of the IPC surface.

## Public API

| Name       | Kind     | Signature                                                              | Description                                         |
| ---------- | -------- | ---------------------------------------------------------------------- | --------------------------------------------------- |
| `COMMANDS` | constant | `const COMMANDS: &[&str]`                                              | The 19 command names the shell registers.           |
| `main`     | function | `fn main() -> Result<(), Box<dyn std::error::Error + Send + Sync>>`    | Runs `tauri_build::try_build` with those commands.  |

## Details

### `COMMANDS`

In order: `vault_status`, `create_vault`, `unlock`, `lock`, `change_master_password`, `regenerate_recovery_code`, `get_settings`, `set_auto_lock_timeout`, `set_clipboard_clear_delay`, `list_items`, `get_item`, `reveal_item_field`, `copy_item_field`, `create_item`, `update_item`, `delete_item`, `add_attachment`, `export_attachment`, `delete_attachment`.

- **Invariant**: it must list the same commands as `tauri::generate_handler!` in [`main.rs`](src/main.rs.md). The doc comment says so, and [`main.rs.tests.md`](src/main.rs.tests.md) checks that the capability grants exactly these names.
- **Security**: a command missing here gets no generated permission, so it cannot be granted and every call to it is rejected. A command present here but not in the capability is also rejected. Either way, a command never becomes callable by accident.

### `main`

1. Builds `tauri_build::AppManifest::new().commands(COMMANDS)`.
2. Calls `tauri_build::try_build(tauri_build::Attributes::new().app_manifest(manifest))`, which, as part of the build:
   - validates and embeds `tauri.conf.json` and the capability files;
   - writes `permissions/autogenerated/<command>.toml` for each command, each with an `allow-<command>` and a `deny-<command>` permission (the identifier uses dashes, for example `allow-change-master-password`);
   - writes the JSON schemas under `gen/schemas/` that the capability file's `$schema` points to.
3. Returns the error instead of panicking, so the build fails with a message and the script needs no `unwrap`.

- **Errors**: any `tauri-build` failure (for example an invalid config or a capability that references an unknown permission) fails the build.

## Dependencies

- **Internal**: reads [`tauri.conf.json`](tauri.conf.json.md) and [`capabilities/default.json`](capabilities/default.json.md) through `tauri-build`.
- **External**: `tauri-build` (build dependency in [`Cargo.toml`](Cargo.toml.md)).

## Used by

- Cargo runs it before compiling the `novavault` package.
- [`src/main.rs`](src/main.rs.md): its test embeds this file with `include_str!` and parses `COMMANDS`.

## Tests

- [`capability_grants_exactly_the_declared_commands`](../../../src-tauri/src/main.rs#L132), documented in [`main.rs.tests.md`](src/main.rs.tests.md): `COMMANDS` mapped to `allow-*` equals the capability's `permissions`, and has 19 entries.

## Notes

- The generated `permissions/autogenerated/` and `gen/schemas/` directories are build output, ignored by `.gitignore` and not documented as files (see [`TEMPLATE.md`](../TEMPLATE.md), _Excluded_). Their content is described in [`default.json.md`](capabilities/default.json.md).
- The module doc says the script "generates Tauri context"; strictly, `tauri-build` prepares the inputs and the `tauri::generate_context!` macro in `main.rs` embeds them at compile time.
- `COMMANDS` and `generate_handler!` are kept in sync by hand; only the capability side is tested.
