# [`src-tauri/src/os_lock/linux.rs`](../../../../../src-tauri/src/os_lock/linux.rs)

## Purpose

The Linux `LockMonitor`. It listens to D-Bus signals from systemd-logind (suspend and session lock) and from the desktop's screen saver service (lock screen active). Every source is optional: a system without logind or without a screen saver service simply provides fewer triggers. Failures are reported on stderr with a fixed message. Unlike the Windows and macOS monitors, this one uses only safe Rust. Compiled only for `target_os = "linux"`.

## Public API

| Name | Kind | Signature | Description |
| ---- | ---- | --------- | ----------- |
| `LinuxMonitor` | struct | `pub struct LinuxMonitor;` | The Linux monitor. |
| `impl LockMonitor for LinuxMonitor` | trait impl | `fn start(&self, sink: LockSink) -> Result<(), MonitorError>` | Spawns the D-Bus watchers and returns at once. |

`LinuxMonitor` is reachable only through [`platform_monitor`](mod.rs.md#platform_monitor). The proxy traits below are private.

## Details

### D-Bus proxies (private, generated by `#[zbus::proxy]`, async only)

| Proxy | Bus | Service / path | Used members |
| ----- | --- | -------------- | ------------ |
| `LoginManager` | system | `org.freedesktop.login1` at `/org/freedesktop/login1`, interface `org.freedesktop.login1.Manager` | `GetSession("auto")`: the caller's session path. `PrepareForSleep(start: bool)` signal: `true` before sleep, `false` after resume. |
| `LoginSession` | system | `org.freedesktop.login1`, interface `org.freedesktop.login1.Session`, path set at runtime | `Lock` signal: the session should lock its screen (`loginctl lock-session` and most desktop environments). |
| `freedesktop::ScreenSaver` | session | `org.freedesktop.ScreenSaver` at `/org/freedesktop/ScreenSaver` | `ActiveChanged(active: bool)` signal (KDE and others). |
| `gnome::ScreenSaver` | session | `org.gnome.ScreenSaver` at `/org/gnome/ScreenSaver` | `ActiveChanged(active: bool)` signal (GNOME). |

The two screen saver proxies live in separate submodules because both signals are named `ActiveChanged`, and the generated types would collide.

### `LinuxMonitor::start`

1. `STARTED.swap(true)`. If it was already set, returns `MonitorError::AlreadyStarted`, so signals are never delivered twice.
2. Spawns two tasks on `tauri::async_runtime`:
   - `watch_logind`. On error it prints `NovaVault: logind is unavailable; no lock on suspend or session lock`.
   - `watch_screen_savers`. On error it prints `NovaVault: the session bus is unavailable; no lock on screen saver`.
3. Returns `Ok(())` immediately.

- **Errors**: only `AlreadyStarted`. Every D-Bus failure is asynchronous and goes to stderr.

### `watch_logind` (private)

1. Connects to the system bus and builds the `LoginManager` proxy.
2. Gets the app's session path with `GetSession("auto")` and builds a `LoginSession` proxy on it.
3. Subscribes to `PrepareForSleep`, keeping only `start == true` as `Suspend`, and to `Lock`, as `ScreenLock`.
4. Merges both streams with `futures_util::stream::select` and calls `sink(reason)` for each event.
5. Fails if a signal's arguments cannot be decoded, or if both streams end.

- **Edge cases and invariants**: one failure in any step disables both logind triggers, suspend and session lock. For example, `GetSession("auto")` fails when the process is not part of a logind session.

### `watch_screen_savers` (private)

1. Connects to the session bus and builds both screen saver proxies.
2. Subscribes to `ActiveChanged` on both. The source notes that subscribing works even if a service is not running: the match rule is registered with the bus, and signals arrive once the service starts.
3. Merges the streams and calls `sink(LockReason::ScreenLock)` for each `true`.
4. Returns `Ok(())` if both streams end. A decoding error ends the watcher with an error.

## Notes

- **Platform differences within Linux**:
  - suspend and session lock need systemd-logind;
  - screen-saver lock needs a service implementing `org.freedesktop.ScreenSaver` (KDE and others) or `org.gnome.ScreenSaver` (GNOME).

  Desktops that provide neither screen saver interface give no screen-saver trigger. Locking then relies on logind's `Session.Lock`, the inactivity timer and manual locking.
- No watcher retries after a failure or after its streams end. A D-Bus restart or a lost connection disables the corresponding triggers until the app restarts. The stderr message in that case is the generic "unavailable" one.
- `watch_screen_savers` returns `Ok(())` when its streams end, so that case prints nothing, while `watch_logind` treats the same situation as an error.
- Unlike Windows and macOS, the lock runs in an async task when the signal arrives. logind's `PrepareForSleep` is a notification, and this code takes no sleep inhibitor lock, so there is no guarantee that the vault locks before the system actually suspends. The code makes no claim either way; this is an open question.
