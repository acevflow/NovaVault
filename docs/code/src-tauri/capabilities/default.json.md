# [`src-tauri/capabilities/default.json`](../../../../src-tauri/capabilities/default.json)

## Purpose

The only Tauri capability of the app, and therefore the complete allow-list of what the webview may call. It grants the `main` window the 19 NovaVault commands and nothing else: no Tauri core permissions and no plugin permissions. Tauri rejects every IPC request that is not covered here, so this file, together with the `COMMANDS` list in [`build.rs`](../build.rs.md), defines the trust boundary between the UI and the Rust shell.

## Public API

### Keys

| Key           | Type   | Value                    | Purpose                                                                            |
| ------------- | ------ | ------------------------ | ---------------------------------------------------------------------------------- |
| `$schema`     | string | `../gen/schemas/desktop-schema.json` | Editor validation against the schema `tauri-build` generates. Not read at runtime. |
| `identifier`  | string | `default`                | Referenced by `app.security.capabilities` in [`tauri.conf.json`](../tauri.conf.json.md). |
| `description` | string | (policy text)            | States the policy: only vault commands; no events, file system, dialog, shell or HTTP; justify any addition in the PR. |
| `windows`     | array  | `["main"]`               | The capability applies only to the window labelled `main`.                         |
| `permissions` | array  | 19 `allow-*` identifiers | The granted commands, below.                                                       |

### Granted permissions

Each `allow-<name>` permission is generated by `tauri-build` from the command `<name with _>` declared in [`build.rs`](../build.rs.md), and allows exactly that command with no scope. The handlers are in [`commands.rs`](../src/commands.rs.md).

| Permission                        | Command                     | What it lets the UI do                                                     |
| --------------------------------- | --------------------------- | -------------------------------------------------------------------------- |
| `allow-vault-status`              | `vault_status`              | Ask whether a vault exists and whether it is unlocked.                     |
| `allow-create-vault`              | `create_vault`              | Create the vault with a master password; receive the recovery code once.  |
| `allow-unlock`                    | `unlock`                    | Unlock with the master password or the recovery code.                     |
| `allow-lock`                      | `lock`                      | Lock the vault.                                                            |
| `allow-change-master-password`    | `change_master_password`    | Re-wrap the vault key under a new master password.                        |
| `allow-regenerate-recovery-code`  | `regenerate_recovery_code`  | Replace the recovery code; receive the new one once.                      |
| `allow-get-settings`              | `get_settings`              | Read the auto-lock timeout and clipboard clear delay.                     |
| `allow-set-auto-lock-timeout`     | `set_auto_lock_timeout`     | Change the auto-lock timeout (1–60 minutes).                              |
| `allow-set-clipboard-clear-delay` | `set_clipboard_clear_delay` | Change the clipboard clear delay (5–300 seconds).                         |
| `allow-list-items`                | `list_items`                | List item summaries (no secret fields).                                   |
| `allow-get-item`                  | `get_item`                  | Read an item's plain fields and "has secret" flags.                       |
| `allow-reveal-item-field`         | `reveal_item_field`         | Reveal one secret field of one item.                                      |
| `allow-copy-item-field`           | `copy_item_field`           | Have Rust copy one field to the clipboard, cleared later.                 |
| `allow-create-item`               | `create_item`               | Create a password, note or secret.                                        |
| `allow-update-item`               | `update_item`               | Update an item; omitted secret fields are kept.                           |
| `allow-delete-item`               | `delete_item`               | Delete an item and its attachments.                                       |
| `allow-add-attachment`            | `add_attachment`            | Have Rust open a file dialog and encrypt the chosen file into the vault.  |
| `allow-export-attachment`         | `export_attachment`         | Have Rust open a save dialog and decrypt an attachment to the chosen file. |
| `allow-delete-attachment`         | `delete_attachment`         | Delete one attachment.                                                    |

## Details

### What is denied, and why

Anything not listed is denied. In particular:

- **No `core:*` permissions.** The webview cannot use Tauri's built-in window, webview, app, path, menu, tray, image or resources APIs, and has no `core:event` permissions, so it can neither listen to nor emit events. The shell does not need them: attachment progress arrives through a `tauri::ipc::Channel` passed as a command argument (`Channel<TransferProgressDto>`), which the capability does not grant separately (Tauri delivers channel messages itself), and auto-lock resets the UI by reloading the webview from Rust ([`autolock.rs`](../src/autolock.rs.md)) rather than by sending an event.
- **No `dialog:*` permissions.** `tauri-plugin-dialog` is registered, but only Rust calls it. The UI cannot open a dialog or receive a file path, so it can never make the shell read or write a file the user did not pick, and no response contains a path.
- **No `fs`, `shell`, `http`, `opener`, `clipboard-manager` or other plugin permissions.** Only the dialog plugin is registered. `tauri-plugin-fs` appears in `Cargo.lock` solely as a dependency of `tauri-plugin-dialog` and is not registered by the app; the other plugins are not dependencies at all. Clipboard access is done in Rust through `arboard` by `copy_item_field`, so the webview never reads the clipboard.
- **No `deny-*` entries.** They are unnecessary: with only `allow-*` grants and no default set, an ungranted command is already rejected.

### Window scope

`windows: ["main"]` matches the single window in [`tauri.conf.json`](../tauri.conf.json.md). A window with another label, if one were ever created, would get no permissions at all. No `webviews` or `remote` keys are set, so remote content (any `https://` page) gets nothing.

### Generated permission files

`tauri-build` writes `src-tauri/permissions/autogenerated/<command>.toml` on every build, one per entry in `COMMANDS`, each defining an `allow-<command>` (`commands.allow = ["<command>"]`) and a `deny-<command>` (`commands.deny = ["<command>"]`) permission without scope. It also writes the schemas under `src-tauri/gen/schemas/`. Both directories are build output, ignored by `.gitignore`, and excluded from per-file documentation by [`TEMPLATE.md`](../../TEMPLATE.md).

## Dependencies

- **Internal**: [`build.rs`](../build.rs.md) (`COMMANDS`, from which the permissions are generated); [`tauri.conf.json`](../tauri.conf.json.md) (enables this capability by identifier and defines the `main` window).
- **External**: the Tauri 2 ACL (capability and permission system) through `tauri-build`.

## Used by

- [`tauri.conf.json`](../tauri.conf.json.md): `app.security.capabilities: ["default"]`.
- [`src/main.rs`](../src/main.rs.md): its test embeds this file.

## Tests

- [`capability_grants_exactly_the_declared_commands`](../../../../src-tauri/src/main.rs#L132), documented in [`main.rs.tests.md`](../src/main.rs.tests.md): the `permissions` array equals `COMMANDS` from `build.rs` mapped to `allow-*`, with 19 entries. Adding any other permission, including a core or plugin one, fails this test.
- `tauri-build` fails the build if a listed permission does not exist.

## Notes

- **Stale local output (not a repository issue):** a working copy built before the attachment commands existed may still have only 16 files in `permissions/autogenerated/`, without `add_attachment`, `export_attachment` and `delete_attachment`. The directory is regenerated on the next build; it is not tracked.
- The `description` lists "events, file system, dialog, shell or HTTP" as not granted; the file grants no other core or plugin permission either.
- Every command is described for UI developers in [`docs/api-reference.md`](../../../api-reference.md).
